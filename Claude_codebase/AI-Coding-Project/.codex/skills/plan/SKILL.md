# Plan the project

When the user is starting out or rethinking direction:

1. Open (or create) `0-project-management/overview.md`.
2. Capture, briefly: **what** this project is and who it's for, **why** it exists, a rough **roadmap** (a checklist of the next few specs), and current **status**.
3. Keep it short and current — this is the orientation a fresh session reads first. Update it as things change rather than letting it go stale.

Plan at the project level here. Detailed "what to build" for a specific feature belongs in a spec (`new-spec`), not the overview.
